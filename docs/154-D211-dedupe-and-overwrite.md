# D211：逐生上传同一学生出现两次（112=56×2）+ 新增「覆盖」原报告

> 日期：2026-11-19
> 状态：**已完成（2026-11-19）**
> 关联：`docs/153-D210-preview-cache.md`、`docs/152-D209-real-confirm-chain.md`
>
> 隐私：测试只用合成数据。

---

## 0. 现场（两个问题）

1. **逐生上传里同一学生出现两次**，报告版本一致、本地分数不同；
   点上传后平台批语里出现**两张报告图**；
   点「重新读取平台状态」**不显示平台分数**。
2. 「上传前对照」显示**已读取平台状态（只读）共 112 人**，
   而班级实际只有 **56 人**（112 = 56×2）。

---

## 1. 根因

### A. 同一学生两个草稿键 → payload 重复

草稿键历史上可能是 `workAnswerId`，也可能是**姓名**。D195 只在**生成报告**时按学生合并，
`drafts_to_payloads()` 仍**按键**产出 payload：

```python
drafts = {"wa_101": {...score 88...}, "学生甲": {...score 95...}}
# → 2 条 payload，同一个学生
```

→ 对照表行数翻倍（112 = 56×2）；逐生上传列表出现重复；点上传会把两条都传上去。

### B. 覆盖时新图被“追加”而不是“替换”

`upload_comment_image()` 走 UEditor 插入，而原批语里已有旧报告图；
上传逻辑又会把“页面里已存在的 `<img>`”拼回批语尾部：

```python
imgs = re.findall(r"<img\b[^>]*>", read_back().comment)
if imgs: html = html + "".join(imgs)     # 保留旧图
```

→ 学生批语里堆成**两张报告图**。

### C. 平台分数取不到时显示空白

逐生读批阅页失败（超时/页面变化）被 `except: pass` 吞掉，
界面只显示 `—`，教师无法判断是“平台没分”还是“没读到”。

---

## 2. 修复

### R1. 按学生去重 payload

`Dedupe_payloads_by_student()`：同名保留“更完整”的一份
（人工套 > 有批语 > 有报告图 > 有分数 > 更新时间），
并合并另一份的**报告版本**与**草稿键**（`draftKeys` 留痕）。

```python
drafts_to_payloads({"wa_101": 88分, "学生甲": 95分})
# → 1 条，分数 95，draftKeys=['wa_101','学生甲']
```

### R2. 新增「覆盖」上传模式

`upload_grade(..., overwrite=True)`：

1. **先清空平台批语框**（移除旧报告图/旧批语）：`set_comment_html(page, "")`；
2. 再上传新报告图；
3. 写入新分数；
4. 覆盖模式自动 `force=True`（等价教师已确认）；
5. 批语文字不再回拼旧图（`if comment_images and not overwrite`）。

CLI：`--overwrite`；serve：透传 `overwrite`；前端：逐生行新增**「覆盖」**按钮
（橙色，点击前二次确认“将清空平台上该生的原批语/原报告图”）。

### R3. 平台分数读取状态可见

- 逐生读取失败 → `platformReadError`（界面显示“读取失败”，hover 看原因）；
- 已批阅但拿不到分数 → `platformScoreUnknown`（显示“未知”）；
- 对照表顶部汇总“有 N 名学生平台分数未能读取”，并提示可重新读取。

## 4. 使用建议

| 场景 | 用哪个按钮 |
|---|---|
| 平台尚未批阅 | 「上传」 |
| 平台已批阅、只想补分/补图且**保留原批语** | 「上传」（会提示冲突并确认） |
| 要**替换**平台原有报告图/批语 | **「覆盖」**（先清空再写新图新分） |
| 只想验证能否填入 | 「演练」 |

---

## 5. 边界

- 「覆盖」会**删除**平台批语框中原有的报告图，属于不可逆操作（有二次确认）；
- 覆盖只清空**作业批语框**，题目批语（若平台有）不受影响；
- 去重后同一学生只上传一次；`draftKeys` 记录被合并的键，便于追溯。
