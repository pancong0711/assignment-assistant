# D145 需求单：provider 请求头 UI 重做（勾选式会话头 / 顺序 / 留空语义 / 保存反馈）

> 日期：2026-10-31
> 状态：**已完成**
> 关联：`docs/86-D136`（x-opencode-session）、`docs/87-D137`（高级请求头入口）、
> `docs/12`

## 0. 教师反馈（原话要点）

1. **没成功配置请求头**，当前操作不符合一般操作习惯；
2. `sessionid` 应该**自动生成**，「如何能输入进请求头？」——不该让用户手写；
3. **高级设置栏应该在保存键上方**（先设置好再保存）；
4. 高级设置默认关闭；打开后写着「留空表示默认值」，但**不填写就保存等于没有请求头**，
   **逻辑混乱**。

## 1. 核查结论（全部成立）

| # | 事实 |
|---|---|
| 1 | `<details>` 高级块排在「保存 provider」**之后**（模板顺序如此） |
| 2 | 引擎侧 session **本就自动生成**（`_headers_for()` 生成 `assist-<hex>` 并缓存），教师**从不需要**提供；界面却要求手写 `x-opencode-session={session}` |
| 3 | 同一区域两个字段的「留空」含义相反：`user-agent` 留空**有默认值**；`请求头` 留空**没有任何头** |
| 4 | 保存成功只提示「key 只掩码显示」，**不说请求头是否存进去了** |
| 5 | 「未分配段 → 不会用到」只是表格里的小橙字，保存时**没有醒目提醒** |

## 2. 设计（定稿）

### 2.1 顺序

```
名称 / base_url / api_key / 支持batch
⚙️ 高级：请求头（折叠，默认关闭）
[保存 provider]  [清空表单]
✅ 保存结果提示（含请求头项数与生效段）
```

### 2.2 勾选式会话头（**不再暴露 `{session}`**）

```
☑ 需要会话头（自动生成会话 id；如兼容 opencode-go）
     头名：[ x-opencode-session ]
```
勾选 = 保存 `{"x-opencode-session": "{session}"}`（占位符由前端代填，教师不写）。
取消勾选 = 移除该项。

**为什么用勾选**：会话 id 是**运行时自动生成**的值，把它暴露成模板变量，
等于要求教师理解实现细节——这正是本次"配不成功"的主因。

### 2.3 「留空」语义写清楚（两块分别标注）

| 区块 | 留空含义 |
|---|---|
| 会话头 | 不勾选 = 不发会话头 |
| 其他自定义头（可选，高级） | 留空 = **不发送任何自定义头** |
| user-agent | 留空 = 使用默认值 `assignment-assistant/<版本>`（**界面显示当前默认值**） |

### 2.4 保存反馈

成功时显示：
`✅ 已保存：请求头 1 项（x-opencode-session）；已分配到 转写段、评阅段`
若未分配段：
`⚠️ 已保存，但该 provider 还没分配到「转写段/评阅段」——现在不会生效`

## 4. 安全（不放宽）

- 白名单不变：只 `x-*` 与 `user-agent`；`Authorization`/`Host`/`Cookie` 仍被拒；
- 二次确认保留（列出将发送的实际内容），但**只在该 provider 真有自定义头时**弹出；
- 会话 id 仍由引擎自动生成（D141），前端只存占位符。

## 5. 验收标准

1. 高级块位于保存键**上方**；
2. 勾「需要会话头」→ 保存后该 provider 的 `headers` 含 `x-opencode-session: {session}`；
3. **界面上不出现 `{session}` 字样**（教师无需理解占位符）；
4. 取消勾选 → 该项被移除；
5. user-agent 留空时显示并使用默认值；
6. 保存后提示含"请求头 N 项"与"已分配到 X 段 / 未分配"；
7. 编辑往返：已配会话头的 provider，编辑时勾选状态正确；
8. pytest / build / selfcheck / 脱敏全绿。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 勾选式只支持一个会话头 | 其他头仍可在「自定义头」里补；头名可改 |
| 教师误勾（provider 不需要） | 服务端多收一个头一般无害；文案说明"仅当 provider 要求时" |
| 自定义头与勾选头重名 | 勾选头优先，并在保存前检测冲突提示 |

## 7. 实施记录（2026-10-31 完成）

### 7.1 顺序修正

- 高级块从「保存键之后」移到**之后 → 之前**；
- 并**顺带修了一个真实布局缺陷**：插入时它落进了那个 `display:flex` 的输入行容器里，
  与「名称/base_url/api_key/支持batch」挤在同一行（`<details>` 高度塌成 1px），
  浏览器测试用坐标差抓了出来（advY 236 vs saveY 235）；
  现已移出容器，成为独立一行（advY 228 vs saveY 260）。

### 7.2 勾选式会话头（不再暴露 `{session}`）

```html
☑ 需要会话头（自动生成会话 id；如 opencode-go 的 /go 路由要求）
     头名 [x-opencode-session]   ← 会话 id 由引擎自动生成并填入，无需你填写
```

- 勾选 → 前端代填 `{"x-opencode-session": "{session}"}`；
- 取消勾选 → 该项移除；
- **头名必须是 `x-` 开头**（否则前端直接报错，不发请求）；
- **重名时勾选头优先**（自定义头里写了同名的死值会被覆盖）。

### 7.3 「留空」语义写清楚

| 区块 | 留空含义（界面已写明） |
|---|---|
| 会话头 | 不勾选 = 不发会话头 |
| 其他自定义头 | 留空 = **不发送任何自定义头** |
| user-agent | 留空 = 使用默认值，并**显示默认值** `assignment-assistant/<版本>` |

### 7.4 保存反馈

成功时：`provider「X」已保存（key 只掩码显示）；请求头 1 项（x-opencode-session）；`
- 已分配段 → `✅ 已分配到 转写段、评阅段 → 会真正生效`
- 未分配段 → `⚠️ 但还没分配到「转写段 / 评阅段」——**现在不会生效**`

### 7.5 编辑回填

`editProvider()` 会把含 `{session}` 的头**拆出来**变成勾选状态，
其余头留在文本框里；因此编辑时教师看到的是「☑ 已勾选」，而不是 `{session}` 占位符。

## 9. 为什么之前"配不成功"（复盘）

1. **要求手写 `{session}`** —— 把运行时自动生成的值暴露成模板语法，
   教师不知道要不要写、写成什么；
2. **高级块在保存键下方** —— 视觉上像"保存完再设置"，顺序反了；
3. **保存后不反馈** —— 只说"已保存"，不说请求头存没存、会不会生效；
4. **未分配段只有小橙字** —— 真正不生效的原因藏在表格一角。

这四条现在都改掉了。**界面不再要求教师理解任何实现细节**：
勾一下、保存、看反馈即可。
