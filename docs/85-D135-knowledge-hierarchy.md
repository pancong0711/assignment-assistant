# D135 待决：知识点层级（上位/下位概念）

> 日期：2026-10-31
> 状态：**待教师拍板方向（未实施）**
> 关联：`docs/78-D130`（§7 预留）、`docs/84-D135`（趋势报告会受益）、`docs/12`

## 0. 问题

当前知识点是**扁平**的（`vocab.py` 模块注释明确写"只做扁平术语，层级暂不做"）。
教师报告与趋势报告把术语平铺成一张表，教师看不出
「动量守恒」与「完全弹性碰撞」其实属于同一块内容（碰撞问题）。

## 1. 四种候选方案

| 方案 | 数据结构 | 用途 | 工作量 |
|---|---|---|---|
| **A. 扁平词表 + 可选 `parent`** | 每术语加 `parent: "力学"` | 报告按"上位 → 下位"分组；统计可上卷 | **小** |
| **B. 两层固定分类** | `chapter` + `topic` + `term` | 按主题聚合、趋势跨章对比 | 中 |
| **C. 任意深度 DAG（多父）** | `parents: [...]` | 同一知识点挂多个上位（物理里常见） | **大**（UI/校验/循环检测/渲染全动） |
| **D. 只预留字段不读** | 加字段但不使用 | 无实际价值 | 极小（等于不做） |

## 2. 倾向方案（待确认）：A

理由：
1. 直接补上最明显的缺口——报告按"块"分组；
2. 与既有 `chapter`（哪一章）天然衔接，不冲突；
3. 单父树，校验只需"parent 存在 + 不成环"，**不引入无限复杂度**；
4. **C 不做**：多父在物理上更准确，但报告/统计用不到，UI/校验成本远大于收益；
   真需要时 A → C 只需把 `parent: str` 改为 `parents: [str]`，不是死路。

## 3. 若采纳 A 的实施口径（草案）

- **数据**：`<ws>/knowledge-terms.json` 的 `terms[].parent`（可选，字符串，指向上位术语名）
- **校验**：parent 必须存在于词表；**禁止自指/间接成环**
- **AI 提议**：`kb vocab suggest-hierarchy`（L1 预览，只写建议文件，**不自动生效**）
- **教师确认**：`kb vocab set-parent --term X --parent Y`（L2，必须确认，记 `confirmed_by`）
- **报告**：教师报告 / 趋势报告按 parent 分组展示；无 parent 的仍平铺（**行为不变**）
- **明确不碰**：标注逻辑、计分逻辑、题库 `related` 列语义

## 4. 不做 / 边界

- 不做多父 DAG（C）；
- 不自动推断层级并生效（AI 只能提议）；
- 不因层级改变任何扣分。
