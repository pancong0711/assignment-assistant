# D123 缺陷修复：班级目录映射漏 `classes/` 前缀 → 批阅报「目录已不存在」

> 日期：2026-10-29
> 状态：已实现并验证
> 关联：`docs/71-D121`（班级目录自动绑定）、`docs/70-D120`（workspace 根语义）

## 1. 现象

```
❌ AI 批阅失败：Error: 学习通班级 153240001 关联的本地目录已不存在：化工25。
请在「AI 辅助批阅」② 区重新选择目录并保存，或运行
`assist xxt class-map --course 236230001 --class 153240001 --dir classes/<班级>`；
也可在学习通重新提取该班级。
```

## 2. 根因

映射表里存的是 **`化工25`**，而真实目录是 **`classes/化工25`** —— **漏了 `classes/` 前缀**。

链条：

| 环节 | 行为（修复前） |
|---|---|
| PWA ② 区输入框 | 自由文本 `<input placeholder="classes/xxx">` |
| 教师输入 | `化工25`（很自然，看到的就是班级名） |
| `set_class_dir()` | `str(class_dir).strip()` **原样存**，**不校验、不规范化** |
| 解析 | `Path(ws) / "化工25"` → `<ws>/化工25` **不存在** → 报错 |

实测复现：映射存 `化工25` → 查找 `<ws>/化工25`（False）→ 真实位置 `<ws>/classes/化工25`（True）。

**这是 D121 引入"解析不到就报错"后暴露出来的存量数据问题**：以前静默回退（造出假目录）时没人注意，现在报错了才发现映射本身是坏的。

## 3. 修复（三层）

| 层 | 内容 |
|---|---|
| **1. 保存时规范化 + 校验** | `classmap.normalize_class_dir()`：缺 `classes/` 前缀且 `classes/<x>` 真实存在 → 自动补全。`set_class_dir()` **保存前校验目录必须存在**，否则抛 `ClassDirResolutionError` 并列出本机可用班级目录 |
| **2. 存量映射自动纠正** | `resolve_or_raise()`：已存映射目录不存在时，先尝试规范化；能对上就**自动回写**并返回 `source="map-fixed"`（教师无需重选） |
| **3. PWA 交互改造** | ② 区自由输入框 → **下拉选择**真实班级目录（`classDirOptions`，来自 roster store）；保存前前端也补前缀；保存失败时展示引擎返回的候选列表 |

引擎端点 `POST /xxt/class-map` 捕获异常返回 **400 + `candidates`**（此前会 500 或静默存坏值）。

## 4. PWA 上如何操作（回答用户提问）

**正常情况下什么都不用做** —— 打开「AI 辅助批阅」时，`resolve_or_raise()` 会自动把
`化工25` 纠正成 `classes/化工25` 并回写。

若仍想手工确认：

```
「AI 辅助批阅」→ ② 班级 ↔ 作业纸目录
  下拉现在直接列出本机真实班级目录（如 classes/化工25）
  选中 → 「保存映射」→ 提示"已关联 153240001 → classes/化工25"
```

CLI 等价：

```bash
assist xxt class-map --list                      # 看当前映射与本地候选
assist xxt class-map --course 236230001 --class 153240001 --dir 化工25
#   ↑ 漏前缀也会自动补成 classes/化工25
```

## 6. 教训

`set_class_dir()` 最初只做了 `strip()`，没有校验目录存在性 —— **一个"保存"操作接受了必然失败的值**，
问题被推迟到几周后的批阅才暴露。

**规则**：凡是"保存一个路径/引用"的地方，都应当在保存时就校验目标存在，
并在保存失败时**给出可选项**，而不是把校验推迟到使用时。
