## 0. 结论

| 问题 | 修复前 | 修复后 |
|---|---|---|
| 会不会中断？ | **会**：同步 HTTP 请求，逐生渲染 PNG；单人生成抛异常 → 整批 500，**已完成的学生虽然文件已落盘，但前端只看到“生成失败”** | **单人不拖垮全班**：失败记入 `failed`，其余继续；返回 `partial` |
| 再点是不是接续？ | **不是**：从头全量重跑；已完成的学生会重新渲染 | **可以续做**：`resume=true` 跳过已有报告的学生；提供「⏯ 续做报告」「↻ 只补失败」按钮 |
| 重复点击安全吗？ | 不安全：并发两次会抢写同名报告文件 | 同一作业**单实例**（409 busy），不会并发渲染 |
| 重复生成会膨胀版本吗？ | — | 不会：版本号=内容哈希，内容不变不产生新版本 |

## 1. 为什么原来会“中断”

`renderReports()` 调用 `POST /xxt/grade/render-from-drafts`，该端点是**同步**的：
读取草稿 → 逐生 `_mode_report_md` → 写 md/html → `html_to_png`（Playwright 开浏览器截图）
→ 写回草稿。任何一名学生抛异常都会冒到顶层 → 整个请求 500。

典型中断来源：
- Playwright 被占用/浏览器启动失败；
- 某学生草稿字段异常（如批语含不可渲染内容）；
- 教师刷新页面、切 tab 导致的请求中断（前端没有取消语义，但服务端仍会跑完）；
- 引擎重启（服务端线程被杀）。

## 2. 修复：逐生原子 + 进度落盘 + 可续做

`engine/src/assist/grading/drafts.py`：

1. **逐生 try/except**：单人失败记 `{key, student, error}`，其余学生继续；
2. **每人完成即写** `reports/.progress.json`：
   ```json
   {"state": "running|done|partial", "total": 40, "done": ["学生甲"],
    "failed": [{"student": "学生乙", "error": "..."}],
    "skipped": [], "reason": "pwa-render", "mode": "full|resume",
    "startedAt": "...", "updatedAt": "...", "current": "学生丙", "processed": 3}
   ```
3. `resume=True`：已有报告图且草稿记录了版本的学生 → 跳过（记入 `skipped`）；
4. `only=[学生…]`：只重做指定学生（用于「只补失败」）；
5. 返回 `{ok, partial, count, reports, failed, skipped, total, hint}`。

`engine/src/assist/serve.py`：

- 同一 `(classDir, taskId, workId)` 的报告生成**单实例**：并发请求返回 409 `busy`；
- `progressOnly: true` → 只读返回 `.progress.json`（不触发生成）。

## 3. 前端

- 「📄 一键生成批阅报告」：全量/续做安全；
- 进度条：`上次中断/已完成 · 已生成 X/Y 人 · 失败 N 人 · 续做跳过 M 人 · 更新于 …`；
- 「⏯ 续做报告（已完成 X/Y）」：只补缺失；
- 「↻ 只补失败 N 人」：只重做失败名单；
- 409 busy → 提示“该作业正在生成报告，请稍候”，不误报失败；
- `partial` 结果 → 「⚠ 部分完成」并列出失败学生姓名。

## 4. 幂等与版本

- 报告版本 = `sha256(markdown)[:6]`：**内容不变，重复生成不会新增版本**（D193）；
- 续做跳过已完成的，只补缺失 → 不会产生重复历史；
- 报告“最新”文件名恒定，历史在 `.versions/`，因此中断也不会留下“半套新文件名”。

## 6. 已知边界

- 服务端是同步请求：**关闭页面/断网不会中止服务端渲染**（会继续跑完并写进度）；
- 引擎进程被杀（重启）时当前那名学生会中断，但 `.progress.json` 保留已完成的名单，
  重启后再点「续做」即可；
- 单张 PNG 渲染仍受 Playwright 超时影响（默认 5s KaTeX + 600ms），
  失败会记入该学生 `failed`，不影响其他学生。
