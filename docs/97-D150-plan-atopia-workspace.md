# D150 规划（待实施）：Atopia 工作区 + 「拷贝到课堂资料」

> 日期：2026-10-31
> 状态：**规划记录，未实施**
> 关联：`docs/95-D148`（Atopia 只读文件能力）、`docs/79-D131`（materials 三硬规则）、
> `docs/88-D138`（知识点两层分类）、`docs/12`

## 0. 教师构想（原话要点）

> 我们原本打算将授课计划和 ppt 直接发给 atopia，或者在课堂资料中设计文件上传/管理功能。
> 这个文件夹还是开放给 atopia 管理比较好，或者 materials 不能动，
> 但 atopia 在自己的工作空间里做一个 materials-copy 文件夹……
> 让 atopia 提取文件内容之后生成 json 格式文件，这些都在 atopia 的工作空间下，
> 然后在课堂资料选项卡中增加一个拷贝/复制 atopia 解析文档的功能键。
> 因为解析文档的内容可能会进入 summary 的评阅中，涉及很多文件关联。
>
> 长远：把教材电子版（图片转写 md）放到 materials 下，让 atopia 整理教材内容，
> 也许 copy 题型也能做合适评阅，知识点分析、题目设计可能全新变化
> —— 比如 atopia 介入做一个 AI 题库，而不局限于现有各类题库。

## 1. 建议方案（待拍板）

### 1.1 三层目录，各管各的

```
<ws>/materials/<chap>/_source/     ← 教师原件（AI 只读）——D131 硬规则 1 不变
<ws>/atopia/work/<chap>/
    _upload/                       ← 教师交给 Atopia 的临时文件（PPT/授课计划）
    _parsed/                       ← Atopia 解析产物（json + 人可读 md）
    manifest.json                  ← 来源/时间/sha/版本，可追溯
```

**为什么不让 Atopia 直接写 `materials/`**：`_source/` 是唯一真源且 AI 永不可写
（D131）。破了这条就没有"未被 AI 改过的原件"了。

### 1.2 「拷贝到课堂资料」按钮（关键安全边界）

```
Atopia 解析完 → 教师看到解析结果预览
             → 点「📥 复制到课堂资料」
             → 引擎写入 materials/<chap>/知识点清单.md（教师显式确认 + 全文展示 + journal）
```

与现有 `materials.confirm` **完全同口径**：因为这份内容会成为 `summary` 批阅依据。

### 1.3 JSON + MD 双写

- `_parsed/<chap>.json`：结构化（知识点/主题/逻辑关系/来源页码）→ 给程序用
- 渲染成 `知识点清单.md` 时复用 D138 的两层分类（章 → 主题 → 术语）

## 2. 需要先定的口径

1. **上传入口放哪**：Atopia 页内上传 vs 课堂资料页上传后"指派给 Atopia 解析"？
2. **解析产物与 `知识点清单.md` 的关系**：是"直接覆盖"还是"生成建议 → 教师合并"？
   （倾向后者，与 D131 的 `.ai.json` 建议机制一致）
3. **教材电子版（长文档）**：是否需要分片/索引？（一次性喂给模型不现实）
4. **AI 题库（长远）**：是否要独立数据结构，还是复用现有 `kb/*.xlsx` 的 kind 体系？

## 3. 明确不做（本轮）

- 不开放 `materials/_source/` 给 AI 写；
- 不让解析产物**自动**进入 `summary` 批阅依据（必须教师显式复制+确认）；
- 不做 AI 自动出题（长远事项，需单独立项）。

## 4. 与 D148 的关系

D148 已给 Atopia **只读**文件能力（`fs.ls/read/search`）。
本规划需要的是**受控写**（写 `atopia/work/`），属于新增能力，需单独评审。
