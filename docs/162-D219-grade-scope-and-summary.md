# D219 修复：批阅键「功能错位」——逐生却评全班、全局空跑却显示完成

> 日期：2026-11-23
> 状态：**已完成（2026-11-23）**
> 关联：`docs/161-D218`、`docs/159-D216`
>
> 隐私：测试只用合成数据。

---

## 0. 现场

1. 整班「转写+批阅」因**时间过长**执行失败；
2. 逐生审核里：一部分显示「已批阅」（有 AI 批语），一部分显示「已转写」（无批语）；
3. 再点**全局批阅键**：没有做批阅，却显示「批阅完成」；
4. 在逐生审核点**某生的「批阅」**：结果**全部未批阅（已转写）的学生都被评了**。

## 1. 根因（三条叠加）

### A. UI 超时 ≠ 任务失败，但任务仍在后台跑

`pollJob()` 最多轮询 `600 × 2s = 20 分钟`，超时只改提示文字：

```ts
const to = `⚠️ ${label}超时（仍在后台执行）`
```

**引擎里的 job 并没有停**。它继续把全班转写/评阅做完 —— 这就是第 4 点“点逐生却评了全班”的真相：
真正干活的是**那个仍在后台运行的全局任务**，不是逐生任务。

### B. 逐生「转写」没有遵守 `only_students`

`_plan_student_images()` 遍历 plan 的全部学生，**没有按 `only_students` 过滤**：

```python
for stu in ((ctx.get("plan") or {}).get("students") or []):
    ...
```

→ 逐生点「转写」会把全班都转写一遍（评阅侧本来是有过滤的）。

### C. 「什么都没做」也报成功

`_run_evaluate()` 对“已有评阅”的学生直接 `continue`（这是省额度的正确行为），
但任务仍以 `done` 结束，PWA 只按 `job.status === 'done'` 显示 `✅ 完成`。

## 2. 修复

### R1. 逐生范围贯穿（转写 + 评阅）

- `_plan_student_images()` 遵守 `only_students`；
- 评阅侧原有过滤保留；
- 结果：逐生「转写 / 批阅 / 转写+批阅」都只处理该生。

### R2. 评阅如实统计

`_run_evaluate()` 产出：

```python
ctx["evaluate_summary"] = {
  "evaluated": N,        # 本次新评
  "skippedExisting": M,  # 已有评阅结果，跳过
  "skippedNoItems": K,   # 无作业纸题目，跳过
  "failed": F,
  "scanned": T,          # 扫描到的转写份数
}
```

- CLI 打印可读一行 + 机器标记 `__GRADE_SUMMARY__{json}`；
- PWA 解析后显示：
  - `✅ …完成（新评 12 · 跳过已有 44 · 无题目 0 · 失败 0）`
  - 若**新评 0**：`⚠️ 本次没有新评阅（…）。如需重评请勾「强制重做」。`

### R3. 同一作业单实例批阅

`serve` 新增 `_GRADE_RUNNING`（按 `courseId:classId:workId:taskId`）：

- 已有任务在跑 → 返回 **409 `stage=busy` + 运行中的 job_id**；
- PWA 收到 `busy` → **接上该任务**继续显示进度（不再并发、不误报失败）。

### R4. 任务持久化 + 可取消

- 批阅 job id 存 `localStorage`（`assignment-grade-job.v1`）；
- 刷新/切页后自动接上未完成任务；
- 超时提示改为「超过 40 分钟仍在后台执行（任务 xxx）」，并显示 **「⏹ 取消任务」**（复用 `/jobs/<id>/cancel`）。

## 5. 使用建议

1. 整班批阅建议在**不切页/不刷新**的情况下等待，或刷新后让页面自动接上；
2. 若确实卡住：点「⏹ 取消任务」→ 再重新发起；
3. 想只补某生：用逐生行内按钮（现在只处理该生）；
4. 想重评已完成的人：必须勾「强制重做」。
