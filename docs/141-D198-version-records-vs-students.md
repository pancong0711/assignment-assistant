## 0. 现场

清理核对结果：

```text
清理核对（未删除）
报告文件 0 个 · 版本索引 106 → 106 条
没有需要清理的内容
```

教师判断“没有清理成功”，因为版本列表仍显示 106 条，而本次作答学生只有 57 名。

## 1. 根因：**106 是“版本记录数”，不是学生数**

报告版本号是**内容哈希**（D193）；同一学生**每次内容变化**都会新增一条历史记录：

```text
record(学生甲, "v1") → 1 条
record(学生甲, "v2") → 2 条     ← 同一学生，两条“版本记录”
```

因此索引条数 = Σ(每生版本数)。复现：53 名学生 × 2 版 = **106 条记录**。
按名单清理只删除“**不属于名单**的学生”的记录 → 一条都不用删，这是**正确行为**，
但旧提示“没有需要清理的内容”没有解释原因，容易被理解成“清理失败”。

## 2. 修复

### R1. 索引构成诊断 `index_stats()`

```json
{"totalRecords": 106, "studentCount": 53, "avgVersions": 2.0,
 "historyRecords": 53, "inRosterRecords": 106, "orphanRecords": 0,
 "orphanStudents": []}
```

- `totalRecords` = 记录条数（版本数）
- `studentCount` = 去重学生数
- `historyRecords` = 各生“最新”之外的历史版本条数
- `orphanRecords/orphanStudents` = 不属于本次名单的记录/学生

### R2. 清理提示说明“为什么没删”

```
没有“多余学生”的报告文件；名单内 53 名学生共 106 条版本记录，
其中 53 条为**历史版本**（不是多余学生）；
若要减少记录数请用「🗜 压缩版本历史」（每生保留最新 1 版）。
```

### R3. 新增「🗜 压缩版本历史」

`compact_index(reports_dir, keep_latest=1, keep_students, dry_run, delete_history_files=False)`：

- 每生只保留最新 N 条索引（默认 1）；
- **默认只压缩索引，不删 `.versions/` 历史文件**（可回退、可追溯）；
- 名单外学生的记录**不代劳**（仍交给「🧹 清理多余报告」，避免悄悄删别人数据）；
- 流程同样是 dry-run 预览 → 确认 → 执行 → 结果卡。

### R4. 版本面板文案

```text
报告版本：53 名学生 / 共 106 条记录（其中 53 条为历史版本，平均 2 版/人）
```

不再只显示“106 条”让人误以为是学生数。

## 3. 两种操作的区别（给教师的判断表）

| 现象 | 用哪个 | 效果 |
|---|---|---|
| 报告里出现**不存在的学生**（旧批次/旧作业包残留） | 🧹 清理多余报告 | 删文件 + 删索引记录 + 删历史目录 |
| 学生都对，只是**记录条数多**（每生多版本） | 🗜 压缩版本历史 | 索引只留最新 1 版；历史文件保留 |
| 想彻底清空重来 | 先 🧹 清理（名单外）→ 再 🔁 重新生成全部报告 | 报告重建，草稿/分数不动 |
