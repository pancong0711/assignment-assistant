## 1. Atopia 权限：**只能写 `atopia/`**

### 1.1 教师判断（正确且更简洁）

> atopia 可以在 /atopia 外进行写操作的话，是有误删旧文档的可能的，
> 其实让 atopia 在自己的文件夹下写就足够了。kb/materials 里的东西可以都复制一份到 /atopia 里，
> 也许都不需要复制，只要 atopia 将增量部分写在自己的文件夹下，
> 然后执行具体操作需要用到这些数据/内容的时候，把这些内容引用到就好了。

### 1.2 我的补充：**不需要「复制」**

教师问"是不是我想的过于简单了"——**不简单，是对的，而且可以更简**：

| 需求 | 现有能力 | 需要复制吗 |
|---|---|---|
| AI 要**读** `kb/` | ✅ `fs.read`（只读）+ `kb.export` 生成 JSON | **不需要**（格式问题用 export 解决） |
| AI 要**写**解析结果 | ✅ 写 `atopia/work/**` | — |
| AI 要**改**题库 | ❌ 不应该直接改 | 写**建议文件**，教师确认后由**引擎**改 |

**关键洞察**：
> **AI 的"读"已经够用了（只读权限），"写"必须严格限制在自己目录。
> 因此"复制"是多余的——复制是为了让 AI 能看到，但 AI 本来就能读。**

**唯一要解决的是格式**：`kb/*.xlsx` 是二进制，AI 读不了。
→ 用**已存在**的 `kb.export` 生成 `kb/export/*.json`，AI 读它即可。

### 1.3 定稿的权限模型

```
AI 可读：整个 workspace（除 *.secrets.json / .runtime / .git / limits.json）
AI 可写：仅 atopia/**
AI 不可写：kb/、materials/、classes/、resources/ 等一切其他目录
生效方式：AI 写建议文件 → 教师确认 → 引擎执行落库
```

**简化后的两级**（替代原 W0/W1/W2 三级）：

| 级别 | 写什么 | 谁执行 |
|---|---|---|
| W0 沙箱写 | `atopia/**`（含 `suggest-*.json`） | **AI 直接写** |
| W1 生效写 | `kb/`、`materials/`、`classes/` | **只能引擎执行**（教师确认后） |

**区别只在文件命名约定**：`suggest-*` 前缀表示"待教师确认"。

### 1.4 需要移除/降级的工具

| 工具 | 现状 | 改为 |
|---|---|---|
| `kb.write`（L2） | AI 直接写 xlsx | ❌ **升为 L3 拒绝** |
| `kb.tag-knowledge.apply`（L2） | AI 直接写题库 | 改为写 `atopia/work/<feat>/suggest-tag.json` |
| `kb.check-knowledge.apply`（L2） | 改写题库 | 同样改建议文件 |
| `materials.confirm`（L2） | AI 可调"确认" | ✅ 保留（它本来就是"确认后生效"的范本） |
| `rules.set`（L2） | 直接改规则 | ✅ 保留（改动小、有快照、可回滚） |

## 2. 工具面治理（教师："工具越来越多，容易出错"）

### 2.1 现状

- **31 个工具**：L0 只读 15 / L1 预览 5 / L2 写入 9 / L3 危险 5；
- 白名单机制（未登记 = 拒绝）；
- 每个工具有 `summary`（短语）+ `params`（类型）。

### 2.2 三项改进

| # | 改进 | 原因 |
|---|---|---|
| 1 | **工具 description 升级**：`summary` → 「何时用 / 何时不用 / 参数示例 / 常见错误」 | 这是 Atopia 的"skill"——它通过 JSON 调用，靠 description 理解 |
| 2 | **工具分组暴露**：按场景（kb/materials/grading/fs/analysis）分组，每次只给模型当前组的工具 | 31 个平铺选择 → 选错概率高 |
| 3 | **CLI help 补 `Examples:` 段** | 外部 agent（hermes/qwenwork）靠 help 学命令 |

### 2.3 关于 skill（教师提到 hermes 伞状 skill）

**现状核实**：项目**已有 skill 系统**（`skills/` + `tools/skill_installer.py`），
但那是给**外部 agent**（qwenwork / workbuddy）用的——它们通过 **shell 跑 `assist` 命令**。

| | 外部 agent | 我们的 Atopia |
|---|---|---|
| 调用方式 | shell 跑 CLI | 注册表调工具（JSON 参数） |
| 需要什么 | SKILL.md（教命令语法） | **工具 description**（JSON schema） |

**结论**：
- ❌ **不给 Atopia 写 skill**（它不需要，它需要好的工具 description）；
- ✅ **做"任务模板"**（见 §3），复用 D151 的模板 CRUD；
- ❌ **不做插件系统**（dsh 风格）——我们的能力已统一在 CLI 子命令里，插件是"外部扩展"，现在不需要。

## 3. Atopia 一键解析（教师："提示词任务很关键"）

### 3.1 教师需求

> atopia 的解析上传的 ppt/教学计划/大纲/教材转写 md/教材 pdf/笔记 pdf 或照片等，
> 是否需要一键功能……这可以做成一个模板提示词也行，就是让大模型完成一个工作流。
> 但是针对具体文档（甚至可能有新文档扩展），可能太细不易实现。

### 3.2 设计：**两段式，不做工作流编排**

```
┌─ 工步 0：抽取（确定性，无 LLM、免费）──────────────────┐
│ _upload/*.{pptx,docx,pdf,md,txt,图片}                    │
│   PPT/Word → officecli（已有 extract_office）             │
│   PDF      → pdftotext；扫描版 → pdftoppm 出页图（已有）   │
│   图片     → 走 vision 分支                                │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 工步 1：AI 结构化（LLM，花钱）──────────────────────┐
│ 任务模板（可改/存/删/另存）+ 抽取文本/页图            │
│   → JSON：{knowledge[], chapters[], outline[], …}     │
│   → 落 atopia/work/<特征名>/_parsed/*.json            │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 工步 2：教师确认 → 复制进课堂资料（D164 已有）────────┐
```

**为什么这样能应对"新文档类型扩展"**：

| 变化 | 改什么 |
|---|---|
| 新增可抽文本格式 | 工步 0 加分支（几行），工步 1 不动 |
| 新增 AI 任务（如生成习题） | 只加**任务模板**，代码零改动 |
| 文档类型完全不同 | 工步 0 加分支 + 任务模板自带 outputSchema |

**明确不做**：用户拖拽编排的工作流（教师判断正确：太细不易实现）。

### 3.3 任务模板（扩展 D151 第 7 类）

在 `CATEGORIES` 增加 `atopia-task`，模板字段扩展：

| 字段 | 说明 |
|---|---|
| `id` / `name` / `text` | 与现有模板一致（可改/存/删/另存/设默认） |
| **`outputSchema`** | 新增：期望的 JSON 结构 |
| **`inputKinds`** | 新增：适用文档类型（`plan`/`ppt`/`textbook`/`note`/`image`） |

**内置三个任务**：

| 任务 id | 输出 | 适用 |
|---|---|---|
| `knowledge-outline`（默认） | `knowledge[]` + `chapters[]` | 授课计划/大纲/教材 |
| `chapter-tag` | 给已有知识点打**章节标签** | 教材/大纲 |
| `example-extract` | `{content, solution, knowledge[], source}` | 教材/PPT 例题 |

### 3.4 知识点自然聚类（教师："不想做章节级别"）

**教师原话**：
> 我们不想做章节级别，而是通过知识点共现情况做自然聚类分析，可以按类来查看，也可以查看全局。
> 不过可以给知识点做章节标签，这部分可以从授课计划大纲教材等文档中分析。

**设计**：

| 概念 | 实现 | 与另一个的关系 |
|---|---|---|
| **自然聚类** | 2508 的 `region_partition()`（louvain，2 阶边关联势） | 正交 |
| **章节标签** | atopia `chapter-tag` 任务产出，写到词表 `chapter` 字段 | 正交 |

**落盘**：`kb/knowledge-clusters.json`

```json
{"version": 1, "generatedAt": "...", "method": "louvain-2nd-order",
 "clusters": [{"id": "c1", "label": "静电学基础", "members": ["库仑定律", "电场强度"]}]}
```

## 4. 可视化：教师质疑得对，我上轮理由错了

### 4.1 我上轮的错误

我说"matplotlib 会让引擎体积暴涨"——**错的**：

| 事实 | 说明 |
|---|---|
| 引擎分发的是**源码 zip**（≈80KB） | 体积不变 |
| `dependencies` 只是**声明** | 用户 `pip install` 时下载 |
| → **源码包不会变大** | ✅ 教师判断正确 |

**我撤回"体积暴涨"这个理由。**

### 4.2 真正的取舍

| 场景 | 方案 | 工作量 |
|---|---|---|
| **教师报告导出**（docx/PDF/PNG） | ✅ **直接用 2508 的 `viz.py`** | 极小 |
| **PWA 页面浏览** | 引擎出 PNG，前端 `<img>` 显示 | 极小 |
| PWA 需要点节点看明细（**后做**） | 引擎算坐标 → 前端 SVG | 中等 |

### 4.3 定稿策略：**两条输出共存**

> **引擎算数（必须）→ 输出两种：PNG（静态报告/页内看图）和 JSON（前端渲染）。**
> 两者共存，按场景选。

**教师问**：「这相当于要将原本的 python 代码全都转成 html/js 吗？」

**答：不需要。** 分工是：

| 事 | 谁做 | 要翻译吗 |
|---|---|---|
| 算共现/聚类/失误率 | 引擎（Python） | ❌ 2508 代码直接搬 |
| 画 PNG | 引擎（Python + matplotlib） | ❌ 直接用 |
| 网页显示 PNG | 前端 | 几行 `<img>` |

**节点明细登记为待做**（`docs/12`），实现时用「引擎算 x/y 坐标 → 前端 SVG + 点击」，**算法永远在 Python**。

### 4.4 依赖影响（教师提醒 start 脚本）

**5 件套**：`matplotlib + networkx + wordcloud + pandas + numpy` 进 `dependencies`。

**现成能力（好事）**：`start.sh` / `start.bat` 每次启动都执行 `pip install -e`，
**会自动补齐新依赖**（教师问的"是否可以根据 dependences 做补充升级"→ **已经能**）。

⚠️ **但要补一个检查**：现在安装失败只写日志、**继续启动** → 引擎起来后
`import matplotlib` 报错，教师看不懂。需要：

```bash
pip install -e "$ENGINE_DIR" && python -c "import matplotlib" \
  || { 明确提示"依赖安装失败，请查看 start.log"; }
```

并在分析功能首次使用时做**依赖自检**（缺包给可读指引，而不是异常堆栈）。

## 5. 架构评估：CLI + 小 agent

### 5.1 优势

| # | 优势 | 体现 |
|---|---|---|
| 1 | **确定性核心 + 灵活外围** | 批阅扣分/题库读写/成绩计算在 CLI（可测、可复现、免费）；agent 做探索性任务 |
| 2 | **单一能力源** | PWA 按钮与 agent 工具调**同一个** Python 函数 |
| 3 | **安全边界清晰** | L2 确认、L3 拒绝、`_source/` 只读——架构级安全 |
| 4 | **可审计** | 所有写入走 journal + 快照，agent 与教师同一条审计线 |

### 5.2 缺陷与对策

| # | 缺陷 | 对策 | 状态 |
|---|---|---|---|
| 1 | 工具面膨胀（31 个） | 按场景分组暴露 + description 升级 | §2 |
| 2 | 提示词散落三处 | 统一到 `prompts.py` 一套 CRUD（加 `atopia-task`） | §3.3 |
| 3 | 分析能力两套（朴素共现 vs 2508） | 2508 整合替换 | D168 |
| 4 | 前后端算法重复风险 | **硬规则：算数一律在引擎，前端只渲染** | §5.3 |
| 5 | 长文档无分片 | atopia 工步 1 加**固定分片策略**（按页/标题） | §3.2 |
| 6 | agent 看不到前端状态 | **不做**（状态同步复杂度远超收益），改为任务参数明确传 | — |

### 5.3 三条铁律（定稿）

> 1. **单一能力源**：PWA 和 AI 调同一个 Python 函数，绝不写两份；
> 2. **写分层**：AI 只写 `atopia/**`；生效写只能引擎执行（教师确认）；
> 3. **白名单执行**：AI 只能跑登记过的子命令，**永远不能任意 shell**。

**附加规则（教师认可的"引擎算数"）**：
> 判据：**"如果 CLI 也要这个结果，就必须在引擎"**。前端只做渲染。

### 5.4 不做的事

| 想法 | 为什么不做 |
|---|---|
| 拖拽工作流编排器 | 文档类型会变，编排器很快变负担（教师判断正确） |
| 让 agent 直接改前端状态 | 状态同步复杂度远超收益 |
| 章节层级树 | 教师明确不要；用聚类 + 标签 |
| 给 Atopia 写 skill 或插件系统 | 能力已在 CLI；插件是外部扩展，现在不需要 |

### 工步 0：`extract_uploads()`（确定性、免费）

| 文件类型 | 抽取方式 |

| png/jpg | 直接进 vision 列表 |

产物落 `_parsed/_extracted/*.text.txt`；**单文件失败不影响其它**（逐文件报错）。

### 工步 1：`parse_with_task()`（AI、花钱）

- 选模板（不传则用该类默认）→ 拼"任务提示词 + 文档内容 + 教师补充说明"；
- 有页图时走 `chat_with_images`，否则走 `chat` + `json_object`；
- 产物只落 `_parsed/<特征名>.json`，**绝不写 `materials/`**（有测试断言）；
- 模型异常返回可读错误，不抛栈。

### 接口 + 前端

- `POST /atopia/work/extract`（工步 0）、`POST /atopia/work/parse`（工步 1）
- Atopia 工作区页签：「🚀 一键解析」区 = ① 抽取（免费）/ ② AI 解析（会花钱，二次确认）
  + 任务下拉 + 补充说明 + 抽取结果表 + 产物预览

### 🐞 顺带修一个**一直坏着**的接口（D151 遗留）

`/prompts/templates` 是**只读**接口，却写在 `do_POST` 里；前端用 **GET** 调用
→ 请求落进 `_static` 兜底 → **302 重定向到 GitHub Pages**，
返回 HTML 而不是 JSON。结果：**提示词模板下拉一直是空的，且不报错**。

已移到 `do_GET`，并加回归测试（检查路由必须位于 `do_GET` 方法体内）。

### 工具分组（`registry.GROUPS`）

| 组 | 数量 | 说明 |
|---|---|---|
| kb | 9 | 题库查看/统计/写建议 |
| materials | 8 | 章节/原件/知识点清单 |
| rules | 4 | 评阅规则 |
| grading | 3 | 知识点建议/要点生成 |
| fs | 3 | workspace 内只读浏览 |
| prompt | 2 | 提示词模板 |
| atopia | 1 | 自己的建议写 |
| misc | 5 | 其它（含 L3） |

- `tools_by_group(ws, ["kb"])` → 只给该组；**选择空间从 35 降到个位数**；
- `GET /atopia/tool-groups` 供前端做"按场景"选择器；
- `/atopia/ask` 支持 `groups: ["kb","materials"]`（不传 = 全部，旧行为不变）。

### 工具说明升级（给模型看的）

`Tool` 新增两个字段：

| 字段 | 给谁看 | 内容 |
|---|---|---|
| `summary` | **教师** | 一句话"这是什么" |
| `when` | **AI** | "何时用 / 何时不用 / 别用的原因" |

`_tool_list_text()` 改用 `when`——模型真正需要的是"什么时候该用"。
全部 35 个工具（含 L3）都补齐了 `when`；L3 的写成"**禁止**：…，只能由教师…"。

### CLI help 的 Examples

`kb` / `materials` 两个最常用组补了 `Examples:` 段（click docstring），
外部 agent 靠它学命令用法。

> **踩坑**：`@cli.group(help="...")` 会**覆盖** docstring。要让 docstring 显示，
> 必须去掉 `help=` 参数。

### 又一次踩到"只读接口放进 do_POST"

`/atopia/tool-groups` 最初写在 `do_POST`，前端 GET → 302 到 Pages。
与 B4 修 `/prompts/templates` 是**同一类错误**。
已移入 `do_GET`，并在测试里加了**逐路由**检查（`test_readonly_routes_are_in_do_get`）。
