# D227：个性化作业纸助手方案（规划）

> 日期：2026-11-25
> 状态：**规划中（仅记录方向，尚未实施）**
> 关联：`docs/169-D226`、`docs/112-D168`（快照/追溯）、`docs/113-D169`（路线/架构）
>
> 目标不是“做一个 AI 出题按钮”，而是让作业纸助手逐步成为教师的主动教学副驾：
> 知道教到哪、学生练过什么、薄弱点在哪、下一次该练什么，并能解释为什么这样选。

---

## 1. 教师现场与核心痛点

当前最现实的问题不是题目不够，而是**题、tag、人、历史之间的关系不可见**：

- tag 一多，教师很难判断某道题是否已经发给某个 tag / 某类学生；
- 同一道题可能被重复发，或者相反，某个知识点长期没有覆盖；
- 批阅结果、知识点标签、授课进度、作业纸组题之间仍是分散的；
- AI 目前更多用于“批阅/作答/标注”，还没有把分析结果回流到**下一次选题**。

用户明确要求：当前**不急于 AI 生成新题**；先把
「分析题目、分析作答、分析授课进度/内容，再到个性化组卷」这条主线做扎实。

---

## 2. 北向目标（North Star）

每次作业纸生成前，系统能回答四个问题并给出可操作建议：

1. **教到哪了？** 当前章节/知识点/题型覆盖到什么程度；
2. **学生练过什么？** 每个学生/tag 最近做过哪些题、掌握如何、是否重复；
3. **这次该练什么？** 基于薄弱点、覆盖缺口、时间间隔和题量约束推荐题目；
4. **为什么这样选？** 每道题有可解释理由，教师可一键调整，系统不擅自发题。

最终形态是“可解释的个性化推荐 + 教师确认”，AI 生成题目只作为远期可选能力。

---

## 3. 分阶段方案

### P0 · 作业发放台账与重复发题预检（最优先）

**目标**：先解决“哪些题发给过哪些人”这个现实问题，不需要 LLM。

**数据**：
- 扩展现有整班输出 sidecar（`docs/112-D168` / `sheetSidecar.ts`）：
  - 当前 sidecar 记录 pad/tag/学生，但缺**每生实际题目 id 列表**；
  - 新增 `questionIds`（可放在 `students[].items` 或独立 `pads[].questionIds` + 学生命中关系）；
  - 保留 `generatedAt`、`packId`、`purpose`，形成不可变事件。
- 新增 workspace 级 `assignment-ledger.jsonl` 或 `assignment-history/`：
  - `eventId / time / class / student / tag / packId / paperId / questionIds / source`；
  - 从历史 sidecar 可导入/重建；
  - 只追加，不覆盖，可审计。

**能力/UI**：
- 作业纸组题时增加「发题预检」面板：
  - 当前题在本班/本 tag/该学生是否发过；
  - 最近一次时间、次数、涉及学生数；
  - 同题是否已在当前作业纸其它 tag 中出现；
  - 可标记“故意复习”，继续保留但不误报。
- tag 覆盖矩阵：行=题目/知识点，列=tag，值=已发次数/最近日期/平均掌握度。
- CLI 对齐：`assist assignment history/check`，PWA 只做展示和确认。

**验收**：
- 生成整班作业纸前能看见重复风险摘要；
- 能从 sidecar 重建至少一次完整发放历史；
- 不改变现有打印/下载主流程。

### P1 · 题目、作答、授课内容的分析层

**目标**：让系统理解“这题考什么、学生答得怎样、最近教了什么”。

- **题目分析**：知识点、题型、难度、认知层级、常见错误、与教材例题/课堂资料关联；
- **作答分析**：逐题得分/证据/confidence、知识点错误模式、班级共性错因；
- **授课进度**：从课堂资料/例题抽取章节与知识点，维护“已教/在教/未教”时间线；
- **覆盖诊断**：KB 知识点覆盖、已练覆盖、薄弱点覆盖三张图。

这一层先产出**分析与建议**，不直接改题库，不直接生成作业纸。

### P2 · 个性化作业纸推荐（不生成新题）

**目标**：从现有题库中选组合，而不是让模型凭空出题。

推荐约束建议：
- 本次必须覆盖的授课知识点（教学进度）；
- 每位学生的薄弱知识点（掌握度最低）；
- 最近 N 天已练题降权，到期复习题可在“故意复习”策略下回升；
- 题型/难度/题量上限，避免一份作业过难或过长；
- tag 分组差异可解释，同一 tag 内保持基本公平；
- 题库重复题/近重复题去重；
- 每题给出入选理由与替代题。

**交互**：系统生成“个性化作业纸草案”→ 教师逐题/整卷确认 → 可替换/锁定 → 再进入现有预览、打印、发布链路。优先级是**可解释、可控**，不是全自动。

### P3 · 远期：AI 设计新题（谨慎）

- 仅在现有题库无法满足覆盖/难度/个性化需求时启用；
- 生成题必须经过：查重、知识点标签、答案校验、难度估计、教师确认；
- 默认不进入正式作业纸，只进入候选池；
- 不在当前阶段实施。

## 4. 建议的数据模型（草案）

```text
assignment_event
  id, generated_at, class_id, pack_id, paper_id, purpose
  students: [{ name, number, tag, question_ids[] }]
  source: sidecar | manual | imported
```

```text
question_feature
  qid, kb, chap, knowledge_terms[], type, difficulty, source, updated_at
```

```text
student_mastery_snapshot
  student_id, knowledge_term, mastery, evidence_count, last_seen_at
```

```text
recommendation
  student/tag, question_ids[], reasons[], constraints, created_at, accepted_at
```

所有写操作沿用现有安全口径：先预览、教师确认、版本可追溯；学生数据留在本机 workspace。

---

## 5. 推进顺序（下一轮可直接开工）

1. **P0-a** 扩展 sidecar：记录每生实际题目 id；
2. **P0-b** 台账导入器：扫描历史 sidecar，生成 `assignment-ledger.jsonl`；
3. **P0-c** `assist assignment history/check` + 组题页「发题预检」；
4. **P0-d** tag × 题目覆盖矩阵；
5. **P1** 把批阅结果/知识点/授课进度汇总为可查询分析；
6. **P2** 基于约束的推荐组卷（先 recommendation，不生成题）。

---

## 6. 成功指标

- 因“忘记发过”导致的重复题：趋近 0；
- 教师组一份作业纸的时间明显下降，但保留最终控制权；
- 每个班/每位学生的知识点覆盖与题量更均衡；
- 推荐理由可解释，教师替换率可作为模型/规则质量指标；
- 不增加学生隐私暴露面：默认本地、最小化、可删除。

---

## 7. 设计红线

- **不自动发题**：任何个性化结果都必须经教师确认；
- **不把 AI 分析当事实**：低置信内容明确标注，不直接改写成绩/掌握度；
- **不牺牲可解释性**：没理由的推荐不进入正式草案；
- **不为了 AI 而 AI**：能用台账规则解决的重复题问题，优先用确定性逻辑；
- **不生成新题也能个性化**：先把现有题库用对、用好。
