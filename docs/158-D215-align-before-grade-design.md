# D215 设计：把「题目是否对得上」从大模型里拿出来，做在批阅之前

> 日期：2026-11-20
> 状态：**方案已定（2026-11-20 教师拍板）；未实施**
> 关联：`docs/157-D214`（批阅提示词组成）、`docs/156-D213`（kind 解析统一）、
> `docs/78`（三层规则）、`docs/16`（标签审计 D172）
>
> 隐私：只用合成数据举例。

---

## 0. 教师提出的问题（三点都成立）

1. **没见到那句“中性提示”**——为什么？
2. **对比做了两次**：批阅提示词里让大模型比对一次；标签审计（纯 Python）又比一次，
   而且**两次互不知晓**。
3. **审计不需要大模型**，让模型再比一次是**浪费 token**；应该用审计的方法替代模型比对，
   让模型专心批阅。

---

## 1. 事实核查

### 1.1 提示确实存在，但只在你没看的那条报告路径里

| 报告路径 | 谁在用 | 是否含“题目不一致”提示 | 是否含“评分依据” |
|---|---|---|---|
| `build_report_md()`（transcript + evaluation） | 引擎 `flow._run_report`（CLI/批量） | ✅ 有 | ✅ 有 |
| `_mode_report_md()`（草稿 ai/human） | **PWA「📄 一键生成批阅报告」/预览** | ❌ 没有 | ❌ 没有 |

更关键：`drafts.py` 写草稿时只保留了
`{score, comment, reportImages, transcript}`，
**`verdict` 与 `question_match` 根本没进草稿**——所以草稿版报告即使想显示也没有数据。

> 结论：提示不是没生成，而是**在 PWA 使用的报告路径与草稿层丢失了**。
> 这是本次设计必须一并修掉的“可见性缺口”。

### 1.2 两次比对确实存在，而且互不知晓

| | ① 标签审计（D172） | ② 批阅提示词里的「先判题目」 |
|---|---|---|
| 实现 | 纯 Python（字面 n-gram + 数值常量重合） | 大模型 |
| 输入 | 学生作答转写 ↔ 题库题目 | 学生转写 ↔ **该 tag 作业纸的题目**（含参考答案） |
| 输出 | 建议 tag / 置信度 / 是否 diff | `question_match.status` + `verdict=suspected-substitution` |
| 成本 | 0 token | 约 **286 字符 / 学生**（实测占最小提示词 24.6%，≈230–290 token） |
| 结果落点 | `audit/tags-audit.json` | `evaluations/<学生>.json` |
| 是否影响批阅 | 只有教师“采用”后才影响下次 | 不阻断、不扣分，只记录 |
| 两者是否互相读取 | ❌ 不读 | ❌ 不读 |

**这就是教师说的浪费**：同一个判断（“学生做的是不是这份卷”），
用两种引擎各做一遍，结果互不校验、互不复用。

---

## 2. 设计原则

> **程序先判「做的是哪份卷」，模型只做「这份卷答得怎么样」。**

三条原则：

1. **单一事实源**：题目对齐只做一次，结果落盘、两处复用（审计 + 批阅前置）；
2. **确定性优先**：能用阈值/相似度算清楚的，不交给模型；
3. **模型只做它擅长的**：理解作答内容、找错、写批语——不再让它做“题目对不对”的裁判。

---

## 3. 目标架构

```
学生转写（questions[] + answers[]）
        │
        ▼
┌─────────────────────────────────────────────┐
│ ① align_student_work()  ← 纯 Python，0 token │
│    · 逐题匹配：转写题目 ↔ 作业包内各作业纸题目   │
│    · 作业纸级聚合：覆盖率 coverage / 差值 margin │
│    · 输出 verdict: match | mismatch | unknown │
│    · 每题带 kb（题库）→ 顺带确定 kind          │
└─────────────────────────────────────────────┘
        │
        ├── match    ──► 直接批阅（提示词删掉“先判题目”，只留一句已核对）
        ├── mismatch ──► 不批阅，提示“疑似错卷 + 建议作业纸/tag”
        └── unknown  ──► 用当前 tag 的作业纸批阅，但标记 unknown + 提示教师复核
        ▼
┌─────────────────────────────────────────────┐
│ ② 批阅提示词（build_grade_prompt）            │
│    · 题目（按对齐结果，只发对得上的题）         │
│    · 每题按**它自己的 kb** 注入题型规则         │
│    · 参考答案 + 学生作答（按对齐映射到题号）     │
│    · 不再要求模型判断题目是否对应               │
└─────────────────────────────────────────────┘
```

## 4. 对齐引擎（`align_student_work`）

### 4.1 输入

| 来源 | 内容 |
|---|---|
| 学生转写 `transcripts/<学生>.json` | `items[]`：每题的 `no` / `content`（学生抄的题干）/ `answer` |
| 作业包 `pack` | 各作业纸（taskpad）及其题目：`no` / `content` / `kb` / `kind` / `solution` |

### 4.2 复用现有匹配器

D172 标签审计已有**纯 Python 匹配器**（字面 2/3-gram Dice + 数值常量重合，
阈值 `minScore / marginMin / minChars` 均在 `grading-rules.json` 可调）。

本设计**不新造算法**，只把它从“整篇 vs 题库题目”改成**逐题粒度**：

- 单题相似度：沿用现有打分函数；
- 作业纸级覆盖率：`coverage = 匹配上的题数 / 该作业纸题数`
  （也计算反向覆盖率，防“整篇只对上一题”误判）；
- 差值：`margin = 最佳作业纸得分 − 次佳作业纸得分`。

### 4.3 输出（落盘到 plan / evaluation）

```json
{
  "verdict": "match",
  "padId": "pad-innovation-01",
  "tag": "innovation",
  "coverage": 0.83,
  "margin": 0.21,
  "questionMap": [
    {"transcriptNo": "1", "padNo": "3", "kb": "innovation", "score": 0.91},
    {"transcriptNo": "2", "padNo": "4", "kb": "problems",   "score": 0.88}
  ],
  "unmatched": ["5"],
  "source": "align-python"
}
```

**额外红利**：`questionMap[].kb` 直接给出**每道题自己的题库**，
于是批阅提示词与算分都能按“这道题真实来源”走——
D213 那类“旧 plan 缺 kind → 回落 problems”的问题从源头消失。

### 4.4 决策矩阵

| verdict | 触发条件（沿用现有审计阈值） | 行为（**已拍板**） |
|---|---|---|
| `match` | coverage / margin 达到审计现有阈值 | 正常批阅；提示词只留一句“已核对”，删掉比对块 |
| `mismatch` | 另一张作业纸显著更高（现有 margin 口径） | **仅警告，仍出分**：结果标 `align=mismatch` 与建议作业纸/tag，批阅照常 |
| `unknown` | 达不到上述阈值 | **完全沿用现状**：按当前 tag 作业纸批阅，标 `unknown` 供复核，不新增档位、不改判定 |

> 决策依据（教师 2026-11-20）：
> 1. **mismatch 不阻断**——教师需要分数先出来，警告只作提示；
> 2. **unknown 判定保持现状**——现有阈值已经够用，本方案**不调整**审计的 unknown 逻辑；
> 3. **不做“一键改用建议作业纸重批”按钮**——改 tag 的入口已存在（逐生/全部），
>    教师改完再点批阅即可，避免继续堆按钮。

## 5. 提示词怎么改（省 token 的关键）

### 现状（每个学生都发）

```
【第一步：先判断题目是否对应】
先核对学生转写中的题目/作答所针对的题目，是否就是下面这份作业纸题目：
- 一致 → question_match.match = true；
- 不一致（题号对不上/题干完全不同/像是另一份作业或学生自制作业纸）→ match = false，
  并在 evidence 中逐字引用……（共 286 字符）
```

### 改造后

**match（绝大多数情况）**：

```
【题目已由程序核对】学生作答与本作业纸匹配（覆盖率 0.83）。请直接逐题评阅。
```

**unknown（兜底，才保留轻量守卫）**：

```
【提示】若发现作答明显不属于下列题目，请在 question_match 注明，不要强行给分。
```

**效果**：

| 指标 | 现状 | 改造后（match） |
|---|---|---|
| 比对提示字符 | 286 | ≈ 40 |
| 每生节省 | — | ≈ 250 字符 ≈ 200–250 token |
| 50 人一个班 | — | ≈ 1.0–1.2 万 token/班 |

> mismatch / unknown 时**保留**那段（或缩短版）比对说明：
> 因为此时仍需模型给出“为什么对不上”的证据，供教师核对后再改 tag 重批。

**不做新按钮**：mismatch 的建议只以**文字**呈现（“建议作业纸 X / tag Y”），
教师用现有的「逐生改 tag / 全部改 tag」按钮修正后重新批阅即可。

## 6. 数据可见性（修掉“没见到提示”）

设计上要求对齐结果**贯穿三层**，否则教师永远看不到：

| 层 | 字段 | 用途 |
|---|---|---|
| `plan.json` | `students[].align` | 批阅前就能看到“这生像不像这份卷” |
| `evaluations/<学生>.json` | `align` + 兼容字段 `question_match`/`verdict` | 审计留痕 |
| `drafts/<classId>.json` | `ai.align`（新增） | **PWA 报告/逐生审核能显示** |
| 报告（草稿版 `_mode_report_md`） | 渲染对齐结论 + 评分依据 | 教师/学生可见 |
| 逐生审核表 | 新增“题目匹配”列 | 一眼看到 mismatch/unknown |

> 注：`question_match` 字段**保留**（由程序填写），旧的报告模板与全局统计不用改。

## 7. 审计与批阅如何共用

```
audit/tags-audit.json  ←─┐
                         ├── 同一个 align_student_work() 结果
plan.students[].align  ←─┘
```

- 审计跑过 → 结果带时间戳缓存；批阅前置直接复用（同一份作业包 + 同一份转写才复用）；
- 转写更新 / 作业包改动 → 缓存失效，重算（纯 Python，成本可忽略）；
- 教师“采用审计建议” → 更新快照 tag → 下次批阅按新 tag 选题（并重新对齐）。

这样两次比对合并成**一次计算、两处消费**，彻底消除“互不知晓”。

## 8. 分阶段落地（建议）

| 阶段 | 内容 | 风险 | 收益 |
|---|---|---|---|
| **P1** | 只计算并落盘对齐结果 + UI 显示（**不改批阅行为**，提示词照旧） | 极低 | 教师可见、可验证阈值 |
| **P2** | match 时删除提示词里的比对块（省 token）；unknown 保留轻量守卫 | 低 | token 下降、模型更专注 |
| **P3** | mismatch 时给出**文字警告 + 建议**（不阻断、不新增按钮） | 低 | 教师可发现错卷并自行改 tag 重批 |
| **P4** | 逐题 kb 贯通到提示词与算分（替代 `_task_default_kb` 猜测） | 中 | 根治 D213 类问题 |
| **P5** | 草稿层/草稿版报告/逐生审核表展示对齐与评分依据 | 低 | 修掉“看不到提示” |

---

## 9. 风险与缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| 手写转写噪声 | 题干识别有错 → 相似度偏低 → 误判 mismatch | 阈值 + `unknown` 兜底；只在 margin 显著时判 mismatch |
| 同题库不同作业纸题目高度重叠 | 难以区分是哪张 | 用**集合覆盖率**而非单题最高分；结合题量/题号分布 |
| 学生没抄题干 | 无法比对 | 降级 `unknown`，用当前 tag 批阅并提示复核 |
| 混合作业纸 | 一份卷多题库 | 逐题对齐天然支持：每题带自己的 kb |
| 审计结果过期 | 转写/作业包变了 | 用（转写 mtime + 包 hash）做缓存键 |

### 由此产生的设计约束

- 对齐结果**只读**：只写 `align` 字段与提示文案，不改动 roster/快照/tag；
- 不新增按钮、不新增弹窗；
- mismatch/unknown 时保留“为什么对不上”的证据文字（供教师判断是否改 tag）；
- `align` 与 `question_match` 并存：前者是程序结论，后者保留给旧报告/统计。

## 12. 一句话

> 把「这学生做的是哪份卷」交给**确定性的程序**（一次计算、两处复用），
> 把「这份卷答得怎么样」留给**大模型**。这样既省 token，又让错卷在批阅前就被拦住，
> 顺便把“每题属于哪个题库”变成对齐的副产品，规则自然按题生效。

## 12. 其他需要讨论的点（附我的建议）

按重要度排序；标 ★ 的建议优先定。

### ★1. 警告显示在哪（不新增按钮，但要让人看见）

| 位置 | 建议 | 理由 |
|---|---|---|
| 逐生审核表 | 新增一列「题目匹配」，显示 `匹配 / 疑似错卷 / 未确定` | 这是教师批阅时盯着的表；此前 `verdict` 根本没显示 |
| 草稿版报告 | 「评分依据」段增加一行对齐结论 + 证据 | 修掉“提示只在 CLI 报告里”的缺口 |
| 学生报告 | 仅保留中性提示（“你转写的题目与作业纸题目有差异”） | 不给学生贴“顶替”标签（沿用 D127 口径） |

> 说明：要做到这些，`drafts.py` 必须把 `align`（以及 `question_match`）写进草稿 `ai` 套——
> 现在这两个字段在草稿层就丢了。

### ★2. 对齐阈值放哪里

审计现有阈值在 `grading-rules.json → tagAudit`（`minScore / marginMin / mediumScore / ...`）。
对齐需要两个新参数：`coverageMin`、`worksheetMarginMin`。

建议：**并入 `tagAudit` 段**（同一套“题目像不像”的口径，避免两套阈值打架），
默认 `coverageMin=0.6`、`worksheetMarginMin=0.15`，可在规则卡里调。

### ★3. 何时计算对齐

建议在 **`build_plan()` 时算**（而不是批阅前临时算）：

- plan 里就能看到每生的对齐结论（教师批阅前可见）；
- 评阅直接复用，不重复算；
- 审计也复用同一结果（真正“一次计算、两处复用”）。

缓存键建议：`转写 mtime + 作业包内容 hash + 阈值版本号`。

### ★4. mismatch 的证据从哪来（能否把模型比对也删掉）

即使 mismatch 只警告，也需要“为什么对不上”的依据。两条路：

| 方案 | token | 质量 |
|---|---|---|
| 保留 LLM 比对块（现状） | 仍花 ~230–290/生 | 证据是自然语言，可读 |
| 由 Python 输出证据（最佳匹配题 + 相似度 + 未匹配题号） | 0 | 机械但确定 |

建议：**先按 P2 只在 match 时删除比对块**；mismatch/unknown 保留 LLM 比对块，
观察一段时间后再决定是否也换成 Python 证据（这一步可省更多 token，但可读性下降）。

### 5. 只有作答、没抄题干的学生

转写里没有题干 → 无法做题目对齐 → 必然 `unknown`。
建议沿用现状：按当前 tag 批阅 + 标 unknown + 提示复核；
提示词里保留“证据不足时 match=true”的既有口径。

### 6. 同一 tag 绑了多张作业纸

现状 `_pad_for(tag)` 只取一张（首个命中）。对齐若发现“同 tag 另一张更像”，
属于**同 tag 内部**的选择问题，不在本次“跨 tag 错卷”范围内。

建议：**本期不处理**；若确有需求，另开需求单支持“一 tag 多卷按对齐结果选卷”。

### 7. 未匹配题的 kind 怎么办

对齐只给**匹配上的题**提供 `kb`；未匹配题仍走现有 `kindSource=fallback` + 报告警告（D213）。
建议维持这个混合策略，并在 `align` 里记录 `unmatched` 题号，便于教师核对。

### 8. 旧数据兼容

`plan.json` / `evaluations/*.json` 没有 `align` 字段时：
UI 与报告显示「未对齐（旧数据）」而不是空白或报错；重新批阅后自动补齐。

### 9. 性能

纯 Python 对齐复杂度 ≈ 学生数 × 转写题数 × 候选题目数。
50 人 × 5 题 × 50 题 ≈ 1.25 万次相似度计算（毫秒级）。
超大题库（数百题）建议先做题目预筛（按章节/关键词），避免每次都全量比对。

### 10. 与 D213 的关系

对齐是“选题是否正确”的判断，D213 是“选中之后按哪套规则算分”。
两者互补：对齐提供**每题真实 kb**，D213 负责**没有 kb 时的可见兜底**。
建议保留 D213 的 `kindSource` 与 `kind_fallback_questions`，不要因为有了对齐就删掉。

## 13. 一句话总结（更新后）

> **程序判断“做的是哪份卷”，模型只评“这份卷答得怎么样”**；
> 对不上时**只警告、仍出分**，建议以文字给出，教师用现有的改 tag 入口修正后重批；
> 不新增按钮、不改 unknown 判定，只把两次比对合并为一次计算、两处复用。
