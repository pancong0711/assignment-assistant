## D74-0 · 背景与现状

- D72 targets 已落地：`assist xxt discover` → `xxt_home()/targets.json` → PWA「选择课程/班级提取」卡勾选 → `assist xxt extract --targets`。
- 现场观察：

## D74-3 · 发现结果本地缓存 + 时间戳 + 刷新 + 差异高亮（核心）

### 现状（已经具备的部分）

| 能力 | 现状 |
|---|---|
| 落盘 | `xxt_home()/targets.json`，含 `{ok, discovered_at, courses[], steps[]}` |
| PWA 读缓存 | `onMounted` 调 `GET /xxt/targets` 直接渲染，不重新开浏览器 |
| 时间戳 | 页面显示「发现时间：…」 |
| 刷新 | 只能点「发现课程/班级」整轮重跑，无轻量刷新概念 |
| 差异 | 无。平台新增/移除/改名的班级看不出来 |

> 结论：**刷新页面/重开页面已经在读本地缓存，效率没问题**；缺的是「陈旧感知 + 变化对比」。

### 需求

1. **快照时间戳与年龄**
   - 卡片显示「上次发现：YYYY-MM-DD HH:mm（N 分钟/小时/天前）」；
   - 年龄配色：< 24h 绿（新鲜）、1–7 天黄（建议刷新）、> 7 天红（强烈建议刷新）。
2. **刷新发现**
   - 按钮「🔄 刷新发现（重新只读扫描）」= 重新跑 `POST /xxt/discover`；
   - **不在页面打开时自动开浏览器**（避免惊扰）；只在年龄超阈值时显示提示横幅。
3. **新旧对比与高亮**
   - 按 `courseId` / `classId` 作身份键；同名不同 id 视为新增/移除；同 id 名字变化视为「改名」；
   - 分类：课程新增 / 课程移除 / 班级新增 / 班级移除 / 改名；
   - 展示：
     - 卡片头摘要：「相比上次：新增 X 门课 / Y 个班，移除 Z 个班」；
     - 新增：绿色 badge「新增」，默认勾选；
     - 移除：红色 + 删除线，checkbox 禁用且默认不勾选（保留展示直到用户「忽略已移除」）；
     - 改名：橙色 badge，显示「旧名 → 新名」。
4. **勾选状态**
   - 新发现结果默认全选（保持现状）；
   - 但**移除项强制不选**；改名/新增保留勾选；
   - 用户手动取消的勾选不跨刷新保留（第一版简单化，待拍板）。

### 存储与接口设计（建议）

**存储**
```
xxt_home()/targets.json                    # 当前快照（含 discovered_at）
xxt_home()/targets-history/<ts>.json       # 历史快照，保留最近 5 份（可配）
```
- 每次 discover 成功：先把当前 `targets.json` 归档进 `targets-history/`，再写新快照；
- 清理策略：只保留最近 N 份（默认 5），旧文件自动删；不参与「清空全部历史 run」（那是 run，不是 discover 快照）。

**接口**
- `POST /xxt/discover`：不变（重新发现，写当前 + 归档上一份）。
- `GET /xxt/targets`：扩展返回 diff（引擎侧算，PWA 不算）：
```json
{
  "ok": true,
  "discovered_at": "2026-10-10 18:20:00",
  "courses": [{"name": "...", "courseId": "123", "classes": [{"name": "...", "classId": "9"}]}],
  "diff": {
    "against_at": "2026-10-08 12:23:17",
    "courses_added":  [{"courseId": "123", "name": "..."}],
    "courses_removed": [{"courseId": "456", "name": "..."}],
    "classes_added":  [{"courseId": "123", "classId": "9", "name": "..."}],
    "classes_removed":[{"courseId": "123", "classId": "7", "name": "..."}],
    "renamed":        [{"courseId": "123", "classId": "9", "old": "...", "new": "..."}]
  }
}
```
- 无上一份快照时 `diff` 为 `null`（PWA 不显示变化摘要）。

### 陈旧数据的应对口径

- **提取永远实时**：作业/名单/通知从不缓存，每次提取重新只读抓取；旧 targets 只影响「选哪些班」。
- 若平台已删除某班而用户仍勾选，提取会在该班失败并写入 run `failures[]`（现有行为，不新增风险）。
- 若平台新增班而用户没刷新，则本次提取不含新班——靠 D74-3 的年龄提示 + 刷新按钮解决。
- 建议（待拍板）：年龄 > 7 天时在「提取所选」前弹一次确认：「发现结果已 N 天未刷新，仍要用旧清单提取吗？」

### 隐私边界

- `targets.json` / `targets-history/` 含真实课程名、班级名（不含学生姓名），仅本机 `xxt_home()`；
- 不入 git、不上传、不经 serve 之外暴露；serve 仍是 loopback/token；
- 文档/截图示例必须用占位名。

### 验收

1. 刷新页面不触发浏览器/网络发现，直接显示缓存 + 时间戳 + 年龄配色；
2. 点「刷新发现」后：时间戳更新、摘要出现变化数量、新增/移除/改名正确高亮；
3. 移除项默认不勾选；新增项默认勾选；
4. `targets-history/` 只保留最近 5 份，旧文件自动清理；
5. 提取仍实时抓取，run `failures[]` 行为不变；
6. `check-secrets.sh` 通过，无真实名入库。

## D74-4 ·（候选，暂不实施）作业级惰性展开

> 来源：用户「先找班级，再按班级找作业，不必遍历所有班」的讨论。

- 现状：`--targets` 粒度到班；选中一个班就会抓它全部作业（最费时的是逐个作业进 mark 取名单）。
- 候选方案：
  1. 发现阶段保持便宜（课程 → 班级，只读侧栏）；
  2. 每个班提供「查看作业」按需按钮，单班拉一次 `work/list` 列出作业（名称 + 待批/已交/未交）；
  3. targets schema 扩展 `courses[].classes[].works[]`（可选，空=全部，向后兼容）；
  4. 提取时只对选中 `workId` 进 mark/取名单，跳过其余作业。
- 收益：多作业班省大量 mark 访问；提供「提取前预览将要抓什么」。
- 代价：发现交互变复杂；需缓存作业清单并套用 D74-3 的时间戳/diff 机制（同一套设计）。
- 建议：D74 先做课程/班级缓存与 diff；D74-4 待 D74-3 验收后另立 D75。

## D74-5 · 问题答复备忘（写进文档，避免重复解释）

- 「历史 run 管理删除」= **物理删除** run JSON + 该 run 截图 + `pages/runs/<run_id>/` HTML 存档；行内「✕ 移出」才是纯前端隐藏。
- 「选择课程/班级提取」与「读提取结果」= **上下游**，不重复：前者决定提取范围并触发提取，后者展示已产出的 run。
- 「班级提取」准确说是 **发现**：只读侧栏列班级，不抓作业/名单/通知；`targets.json` 是内部缓存，不是给用户导出的产物。
- 按钮从灰变可点 = `selectedCount()` 由 0 变为 12（targets 已加载且默认全选），属预期行为。

- 不做自动后台发现（避免无感开浏览器）。
