## 1. 核心指标定义

### 1.1 为什么不用"得分率"

| 场景 | 2508（期末考试） | 本项目（作业） |
|---|---|---|
| 每题是否有固定满分 | ✅ 有（如 2 分） | ❌ **无**（扣分制、扣分有上限） |
| 得分率 `S_k = 1 − Σa/ΣF` | 有意义 | **无意义**（分母不固定） |
| 失误统计 | 可用但非主 | ✅ **更准** |

**教师原话**：
> 我们的评阅标准是扣分制且扣分有上限（并不固定每题总分，主要为鼓励及时提交），
> 所以从得分看困难，**失分次数**好统计。比如一张作业纸 4 道题，其中 2 道提到同一知识点
> 且学生都错了，则该知识点错了 **2 次**。

### 1.2 指标命名（教师拍板）

| 中文名 | 英文键 | 定义 | 单位 |
|---|---|---|---|
| **加权失误率** | `weightedErrorRate` | 见 §1.3 | **次/人** |
| 失误次数 | `errorCount` | 该知识点被 error 提及的总次数 | 次 |
| 出错人数 | `errStudents` | 至少错 1 次的学生数 | 人 |
| 提交率 | `submitRate` | 实交人数 / 应交人数（快照口径） | % |
| 可信度 | `confidence` | 见 §1.5 | `ok` / `low` |

> ❌ 不叫「人均错误次数」（易误解为简单平均）
> ❌ 不叫「失分率」（与 2508 的分数比混淆）
> ✅ 叫「**加权失误率**」，注释里写明计算式

### 1.3 加权失误率公式

**单班、分 tag**（最常用）：

```
E_k(班, tag) = 该 tag 内该知识点的失误次数 / 该 tag 提交人数
W(tag)       = 该 tag 提交人数 / 该班全部提交人数
W_k(班)      = Σ_tag [ E_k(班, tag) × W(tag) ]
```

**跨班**（两层加权，教师确认）：

```
W_k = Σ_班 Σ_tag [ E_k(班,tag) × (该班该tag提交人数 / 全部提交人数) ]
```

**跨包**（教师拍板：按**总题数**归一）：

```
W_k(跨包) = Σ_包 (该包该知识点失误次数) / Σ_包 (该包总题数)
```

> ⚠️ 待确认：教师原话"跨包不按题数归一，可按总题数归一"存在两种读法，
> 本文按「总失误次数 ÷ 总题数」实现（物理含义：平均每道题该知识点失误多少）。
> 若理解有误，实施前需再确认（`docs/12` 已登记）。

### 1.4 粒度层次（教师："模糊全局 + 不同尺度细节"）

| 层 | 范围 | 用途 | 优先级 |
|---|---|---|---|
| ① 全局 | 所有班/包/tag 合并 | 宏观判断 | P1 |
| ② 分班 | `W_k(班)` | 班级差异 | P1 |
| ③ **分班分 tag** | `W_k(班, tag)` | **最小推荐尺度**（教师 5.1） | **P1** |
| ④ 分班分 tag 分包 | `W_k(班, tag, 包)` | 单次作业细节 | P2 |
| ⑤ 单个学生 | —— | **不做主方向**（偶然性大，教师 5.1） | 不做 |

> 教师 5.1 原话：「倾向于按 tag 分析作为最小尺度……细化到每位学生偶然性更多，
> 不易发现群体规律，可以考虑做这样的细节工作，但应该不是我们的主力方向。」

### 1.5 可信度判据（教师 1.3 关切）

**教师原话**：
> 某 tag 未提交时权重设为 0 是合理的，但如果单独对这个 tag 分析，
> 是否会出现「失误率很低但其实提交人数很少、且提交时正确率较高」的情况？

**是的，这是真实风险。** 保护措施：

| 条件 | 标记 |
|---|---|
| 提交率 < 60% | ⚠️ `low` |
| 提交人数 < 5 | ⚠️ `low` |
| 两者都满足 | ⚠️ `low` |
| 否则 | ✅ `ok` |

**强制规则（教师确认）**：
> **任何失误率数字，必须与提交率成对出现。**

报告格式示例：

| tag | 提交率 | 加权失误率 | 样本量 | 可信度 |
|---|---|---|---|---|
| top | 10% (2/20) | 0.00 | 2 人 | ⚠️ 样本不足 |
| middle | 85% (17/20) | 1.24 | 17 人 | ✅ |

### 1.6 辛普森悖论保护（教师 1.1 关切）

**教师原话**：
> 班级人数不同，全部放一起做加权处理，可能因为人数多的班级对某一知识点的高正确/错误率
> 而影响我们对整体的判断。没关系，我们先这样做……所以我们还要以班级为单位进行统计。

**保护措施**（不改公式，只加展示）：

1. **始终并列显示**「合并值」与「分班级值」；
2. 若某班与全局差异 **> 50%**，标 ⚠️「该班主导/偏离」；
3. 报告不得只给合并值。

## 2. 知识点共现：两套图 + tag 拆分

### 2.1 两套共现图（教师提出，已确认）

| | **标准共现图**（课程资料） | **作答共现图**（作业题） |
|---|---|---|
| 数据源 | **例题**的知识点标注 | 批阅 `errors[].knowledge[]` |
| 含义 | 老师怎么教、知识点怎么组织 | 学生怎么错、哪些概念连带出错 |
| 用途 | 课程结构检查、备课参考 | 教学诊断、针对性补救 |
| 依赖 | **需要例题题库**（见 §2.3） | 已有数据 |

> 教师原话：「大纲、ppt、授课计划应该不支持这样的数据（共现），
> 这里其实还要求我们的 app 可以提取例题做一个题库。」

### 2.2 tag 必须拆分（教师 1.3.1）

**教师原话**：
> 每一个 tag 其实也对应一个知识点共现图。作业包可以把全部知识点共现混在一起，
> 但对于 tag 来讲，是要拆开的。

**理由**：混着算会让共现图"糊成一团"——
- top 学生错的是"高阶综合应用"；
- middle 学生错的是"基础概念混淆"；
- 合并后失去诊断价值。

**接口设计**：

```
GET /kb/analysis?classes=A,B&packs=P1,P2&tags=top&groupBy=tag
→ {
    "global": { "errorRate": [...], "cooccurrence": {...}, "clusters": {...} },
    "groups": { "top": {...}, "middle": {...} }
  }
```

**前端**：顶部一张全局图 + 下方每个 tag 一张小图（可折叠）。

### 2.3 例题题库（`example` kind）

为了支撑标准共现图，需要从授课计划/教材/PPT 抽出**例题**。

| 项 | 决定 |
|---|---|
| kind 名 | **`example`**（教师拍板："新 kind，example 命名很好"） |
| 内容 | 题干 + 解答 + 知识点 + 来源（文档/页） |
| 用途 | **只做分析**，不布置给学生、不进批阅 |
| 与 `problems` 关系 | 独立，互不污染 |

## 3. 数据快照（核心：保证历史可复现）

### 3.1 问题（教师提出）

> 如果我们没有批阅完当前作业，换了一个新的作业包的作答图片，所依据的 roster 是不是也要变？
> 想批阅之前的作业时，roster 是否会切回原来的 roster？这关系到批阅依据的 tag。

**代码现状核实**：

- 批阅时 tag 来自 **`plan` 快照**（`flow.py:296` `stu.get("tag")`），不是实时读 roster；
- 每个包写 `pack.json`（含 `pads[{padId, tag, questionCount}]`）；
- ❌ **但没有学生级 tag 映射**，也没有 roster 快照；
- ❌ **roster 变更后，历史批阅依据不可复现**（`pack.json` 会被覆盖）。

### 3.2 解决方案：包级 roster 快照

```
classes/<班>/
  roster.xlsx                      ← 主名单（唯一真源，可变）
  roster-tags/<packId>.json        ← 按包快照（新增）
```

**快照内容**：

```json
{
  "classDir": "classes/化工251",
  "packId": "homework1",
  "generatedAt": "2026-11-05 10:00:00",
  "source": "recompute-tags | auto-at-grade | manual-refresh",
  "students": [
    {"number": "2023001", "name": "张三", "tag": "top", "composite": 88.5}
  ]
}
```

**关键决定**：
- ✅ **主键用学号**（`number`），姓名只做显示（防改名/重名）；
- ✅ 路径用**子目录** `roster-tags/` 而非文件名后缀（改包名不失效、便于列目录）。

### 3.3 快照写入时机（教师提议 + 补充）

**教师使用习惯（关键信息）**：
> 预览整班的作业纸之后打印 PDF 保存了，而不是生成 batch 或 json 文件，
> 这样一些信息就有可能丢失。

**写入策略（两者都做）**：

| 时机 | 行为 | source 标注 |
|---|---|---|
| 「重算并打 tag」时**选了作业包** | 立即写快照 | `recompute-tags` |
| 批阅时**若没有快照** | 自动用当前 roster 补写 | `auto-at-grade` |
| 教师显式点「刷新快照」 | 覆盖，并提示影响 | `manual-refresh` |

**UI 需求**：「重算并打 tag」旁加**包选择下拉**：

```
本次结果关联到：[<不关联> / 作业包1 / 作业包2 ...]
```

- 不关联 = 只更新班级 roster（现状行为不变）；
- 选了包 = 同时写 `roster-tags/<packId>.json`。

### 3.4 作答名单快照：`submissions.json`（新增）

**教师问**：
> 学生作答的图片下载后应该也有对应的 json 文件记录大家的作答情况（包括图片张数），
> 毕竟 PWA 网页上的逐生预览已经可以显示这些学生了，找到这个名单和 roster/roster-snapshot 就可以对比了，是不是？

**答案：PWA 能显示，是因为它用的是前端传入的 `plan`；引擎侧没有落盘名单。**
所以需要**新增** `submissions.json`：

```json
{
  "packId": "homework1",
  "generatedAt": "2026-11-05 10:00:00",
  "source": "plan | images_dir | xxt",
  "submitted": [
    {"number": "2023001", "name": "张三", "tag": "top",
     "images": ["1.png", "2.png"], "imageCount": 2}
  ],
  "unrecognized": ["weird-name.png"]
}
```

**位置**：`classes/<班>/grading/<packId>/submissions.json`

### 3.5 提交率计算（教师确认）

**定义**：
```
应交人数 = roster-tags/<packId>.json 中该 tag 的人数
实交人数 = submissions.json 中该 tag 的人数
提交率   = 实交 / 应交
```

> 教师原话：「提交率来自已下载的学生作业作答图片里的学生名单跟 roster 里的学生名单进行对比。」

**边界处理**：

| 情况 | 处理 |
|---|---|
| 同一学生多张图 | 按学号去重，`imageCount` 记张数 |
| 图片识别不出是谁 | 计入 `unrecognized`，单独报数量 |
| 学生转入 | 不在旧包快照 → 不统计 |
| 学生转出 | 仍在快照 → 若未交，计入未提交 |

### 3.6 完整链路

```
① 导入 roster（可变，唯一真源）
       ↓
② 「重算并打 tag」+ 选包 → 写 roster-tags/<packId>.json
       ↓
③ 预览整班 PDF / 打印（零元数据，但 roster 快照已存）
       ↓
④ 批阅 → 写 submissions.json
       ↓
⑤ 统计 = submissions.json ÷ roster-tags/<packId>.json
           + 失误次数（来自 evaluations/*.json 的 errors[].knowledge[]）
```

**统计口径决定**：**始终用快照**（保证可复现），报告注明快照时间。

## 4. 知识点标注与受控词表

### 4.1 受控词表是什么（教师问「还没完全理解」）

**定义**：一份「允许使用的知识点名称清单」，用来**防止同一概念有多种写法**。

**为什么需要**：

| 不同写法 | 其实是同一个概念 |
|---|---|
| 动量守恒 / 动量守恒定律 / 动量守恒律 / 动量守恒原理 | ← |

不归并 → 统计变成 4 个知识点，每个样本都很少 → **共现与失误率失真**。

**现有实现**（`knowledge-terms.json`）：

```json
{"version": 1,
 "terms": [{"term": "动量守恒",
            "aliases": ["动量守恒定律", "动量守恒律"],
            "chapter": "chap04", "topic": "守恒定律",
            "source": "human", "count": 12}]}
```

**现有不足（需修）**：

| 现状 | 问题 | 修改 |
|---|---|---|
| `split_terms()` 只做分隔符标准化 | **不做别名归并** | 增加 aliases → term 映射 |
| 无强制约束 | AI 随意写 | 统计只计词表内 + 单独列「词表外」 |
| 需手动 harvest | 不自动更新 | AI 发现新术语入「候补区」`pending`，教师确认转正 |

### 4.2 标注来源与人机结合（教师拍板）

**教师原话**：
> 人工清空知识点以后 AI 应该可以补充，除了误删，应该就是用户对知识点的整理不满意才做删除，
> 另，这里也必须留有用户操作的可能，相当于人机结合。

| 操作 | 行为 |
|---|---|
| 人工清空 `related` | 记为 **「待补」**（AI 可重新标） |
| 人工要锁定「这题确实没有知识点」 | 显式勾选「锁定为空」（`pinned_by=human` + 空） |
| 人工修改 | 锁定，AI 不覆盖 |
| AI 标注 | 只标空白/待补的题 |

**关键**：「清空」与「锁定为空」**分开**——默认清空=待补。

### 4.3 失误统计的知识点过滤（教师关切）

**教师原话**：
> 只统计受控词表内或 related 内的知识点是比较合理的。

**规则**：
- ✅ 计入：能对上**词表 term/alias** 或**题库 `related` 标注**的术语；
- ⚠️ 单独列：对不上的术语（`unclassified`）**只报数量，不进主统计**；
- 避免同一概念被拆成三四条导致失真。

JSON 用**原子写**（临时文件 + replace）。

### 批阅集成：`flow._write_grade_snapshots()`

**关键行为**（这是"保证可复现"的落点）：

1. **快照存在 → 学生 tag 以快照为准**（即使前端 plan 里 tag 变了），并记日志；
2. 快照不存在 → 自动补写，`source=auto-at-grade`；
3. 每次批阅刷新 `submissions.json`；
4. 快照与当前 roster 不一致 → **警告但不阻断**，提示去刷新；
5. **任何快照失败只告警，绝不影响批阅**。

### 关于 T5 的调整（`pack.json` 不重复存 tag）

原计划在 `pack.json` 里加学生级 tag 映射。实施时发现**没有必要**：

- `pack.json` 记的是"这个包用了哪些作业纸（padId + tag）"——**包级**信息；
- 学生级 tag 已在 `roster-tags/<packId>.json`——**人员级**信息；
- 两处都存会产生"改了一处忘另一处"的风险。

**决定**：`pack.json` 保持不变；学生级映射**唯一真源 = `roster-tags/<packId>.json`**。

## 4.5 B2 实施记录（2026-11-05 完成，T6–T10）

### 新增 `grading/error_stats.py`

| 函数 | 作用 |
|---|---|
| `collect_errors()` | 从 `evaluations/*.json` 计失误次数；**同一题同一知识点错 2 次记 2 次**；低置信度不计 |
| `weighted_error_rate()` | 按 tag 失误率 → 按**已提交人数**占比加权（不是班级人数） |
| `confidence()` | 提交率 < 60% 或人数 < 5 → `low`（防"提交少+正确率高→假性低失误率"） |
| `cross_pack_rate()` | 跨包 = **Σ失误 ÷ Σ总题数**（教师拍板，非按包平均） |
| `build_report()` | 一站式：统计 + 加权 + 可信度 + 分 tag 明细 |

### 新增 `grading/cooccurrence.py`

| 函数 | 作用 |
|---|---|
| `occurrence_prob()` | 一阶：知识点在多少比例的题里出错 |
| `cooccurrence()` | n 元共现 + **归一化关联** `P(组合) / ∏P(单项)` |
| `by_tag()` | **每个 tag 一张图** + 全局图 |
| `natural_clusters()` | 按共现耦合做自然聚类（不依赖章节层级） |

### 词表别名归并（`vocab.py`）

- `alias_map()` / `normalize_terms()` / `split_terms_normalized()`：别名 → 规范名；
- `term_tags()`：术语标签（对齐 2508 `考点词表.yaml` 的 tags）；
- `add_alias()`：追加别名（含"已被其它术语占用"的冲突拒绝）。

### 两个调试中发现的问题（都已修正并写进测试）

1. **🔴 归一化关联恒等于 1.0**：原实现写成"rate 逐个除以单项概率"，
   每次除法又把 `total` 乘回去 → 结果永远是 1.0。改为先算分母再除。
2. **🔴 空词表导致统计全空**：`only_known=True` 时，词表为空会把**所有**术语
   打进"词表外"，主统计为空。修正为：**词表为空 = 尚未建立词表，全部视为已认可**；
   只有"建立了词表但术语不在其中"才算词表外。

### 报告口径修正（`teacher_report.collect_multi`）

- tag **优先取该包的 roster 快照**（`_tag_map_for_pack`），无快照才回落当前名单；
- 每条记录补 `tag` 与 `_tagSource`（`snapshot` / `roster` / `none`），
  前端据此提示"tag 取自当前名单，建议先冻结快照"。

| 路由 | 说明 |
|---|---|
| `GET /analysis/errors?classes=&packs=&tags=&onlyKnown=` | 加权失误率 + 跨包 + 可信度 + 分 tag |
| `GET /analysis/cooccurrence?classes=&packs=&tags=&n=` | 每 tag 一张共现图 + 自然聚类 |

### 前端

`KnowledgeView` 新增「⑤-B 知识点失误分析」卡：统计按钮 + 提交人数/权重 +
**可信度警告** + 失误率表（含分 tag 明细）+ 词表外计数 + 跨包口径 + 每个 tag 的共现图 + 聚类。

## 4.8 T13 实施记录（2026-11-05 完成，整班输出追溯 sidecar）

### 问题（教师 §3.3 原话）

> 预览整班的作业纸之后打印 PDF 保存了，而不是生成 batch 或 json 文件，
> 这样一些信息就有可能丢失。

**打印出来的 PDF 是零元数据的**——事后无法回答"这份 PDF 对应哪个作业包、
发给哪些学生、谁什么 tag"。

### 实施

新增 `app/src/lib/sheetSidecar.ts`（**纯函数**，便于单测）：

| 导出 | 作用 |
|---|---|
| `buildSheetSidecar()` | 生成 sidecar 内容 |
| `sidecarFileName()` | HTML 名 → 同名 `.json`（便于配对） |

**记录内容**：

```json
{"version": 1, "kind": "class-sheet-output", "generatedAt": "...",
 "packId": "hw1", "packName": "第一次作业", "purpose": "print|download",
 "pads": [{"padId": "pad-top", "tag": "top"}],
 "students": [{"name": "张三", "number": "2023001", "tag": "top", "padId": "pad-top"}],
 "options": {"includeAnswers": false, "includeWatermark": true, "includePageText": true},
 "unboundTags": ["unknown_tag"],
 "counts": {"students": 4, "pads": 2}}
```

### 落点（重要：不是那个禁用按钮）

排查发现：`SheetOutputSection` 的「🖨 打印级 PDF（模板，需引擎）」是**禁用占位按钮**
（点击只弹提示）。教师真实使用的路径是**「班级与标签」页的整班预览**：

- `printClassPreview()`（🖨 打印整班）→ **先产出 sidecar，再打开打印对话框**；
- `downloadClassPreviewHtml()`（下载 HTML）→ **与 HTML 同批产出 sidecar**。

### 关键设计

- `padId` 由 **tag → 作业纸绑定**推出（`padByStudent` 可显式覆盖）；
- `unboundTags` **显式列出**未绑定 tag 的学生——事后能看出"这些人当时没作业纸"；
- 开关（含答案/水印/页码）一并记录，便于复现同一版式；
- sidecar **只描述输出**，不改任何生效数据。
